ArxJIT

ArxJIT

ArxJIT is a developing Numba-style decorator path from a restricted subset of pure Python to ASTx, IRx, LLVM, and native callable code.

Current behavior: decorated calls execute the original Python function. Initial Python-AST-to-ASTx lowering exists as a public, fail-closed stage, but the decorator does not invoke it and native compilation has not landed.

Implemented foundations

  • @jit and JitFunction
  • explicit scalar signatures using i32, i64, f32, f64, and bool_
  • function-source extraction with corrected real-file source locations
  • structured errors when source cannot be retrieved or parsed
  • exhaustive validation and diagnostics for the proposed Python subset
  • signature reconciliation from explicit signatures or reserved scalar annotations
  • initial ASTx lowering for function shells, typed arguments and returns, scalar literals, parameter reads, arithmetic, supported unary operators, and single comparisons
from arxjit import i64, jit


@jit(signature=i64(i64, i64), cache=True)
def add(left, right):
    return left + right


assert add(20, 22) == 42  # Python fallback in the current implementation

The current validator accepts scalar expressions, assignments, if/else, while, for over the unshadowed builtin range, and returns. Collections, closures, imports, methods, async code, generators, exceptions, attributes, and subscripting are rejected.

The lowerer deliberately covers less than the validator. Assignments, Boolean short-circuit expressions, chained comparisons, and control flow still fail closed in lowering rather than producing an incomplete ASTx module.

Deferred pipeline

Python function
  -> source extraction       implemented
  -> Python AST validation   implemented
  -> signature resolution    implemented
  -> ASTx lowering           initial straight-line subset
  -> IRx native compilation  not implemented
  -> Python-callable bridge  not implemented

Arrow-backed arrays and tensors are intentionally deferred until scalar compilation and runtime marshalling are stable.

See the Python-to-ASTx design for the implemented frontend stages and remaining compilation work.
