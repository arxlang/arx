Unreleased

Python-inspired exceptions (breaking)

  • raise, ordered except handlers, else, and finally now propagate across generated calls. Builtin and single-inheritance user exception classes use ordinary nominal identities; causes and dynamic bare re-raise are supported.
  • Checked numeric, assertion, bounds, file, and Arrow/CSV/Parquet failures are catchable. Finalizers and owned-resource cleanup run before propagation; implicit cleanup preserves a primary failure and records secondary failures.
  • try, except, finally, and raise are reserved keywords. ASTx now models cause/else clauses and qualified handler references; ThrowStmt.get_struct() names its children. Empty handler type lists are not catch-all handlers.
  • Generated functions and runtime callbacks use a context/status/result-slot ABI; rebuild all native producers and consumers together. Ordinary external C signatures remain unchanged. Uncaught failures use structured exception reports; ArxPy exposes them as execution-result data, not Python exceptions.
  • Protected regions spanning generator suspension, Python traceback mutation, exception groups, asynchronous exceptions, and ArxJIT exception lowering remain unsupported. See the support boundary.

Checked numeric promotion (breaking)

  • Numeric promotion and implicit conversions are now lossless across the whole source domain. Mixed signed/unsigned comparisons no longer reinterpret negatives; combinations without a common domain require an explicit cast.
  • Integer arithmetic and numeric casts now fail on out-of-range results in all builds. Source literals retain context and signed minima until type checking. math.square preserves its selected type and fails on overflow; widen its input or explicitly select a wider specialization before computing.
  • Use wrapping_add, wrapping_sub, wrapping_mul, and wrapping_cast only where modulo arithmetic is intended. Ordinary narrowing no longer truncates silently. Nonidentity Series/tensor casts are explicitly unsupported.
  • ArxJIT lowering shares IRx numeric promotion; integer source literals use i32-then-i64 inference and must remain exact in floating contexts. Python @jit fallback and the reserved int annotation (i64) are unchanged.
  • ASTx contextual numeric nodes are LiteralInteger and LiteralFloat, in astx.literals. LiteralFloat accepts exact decimal text or Decimal, not Python float. These replace SourceInteger/SourceFloat without aliases. IRx preserves literal payloads and resolves types and rounded values only in semantic metadata, avoiding decimal-to-f32/f16 double rounding.
  • Direct ASTx/IRx clients must analyze numeric nodes before lowering. Arithmetic and conversion plans, including union storage, are authoritative sidecars. See the numeric safety contract.

Integer helper safety and templates

  • range now terminates without wrapping when a step crosses an i32 endpoint; it still returns an eagerly allocated list[i32].
  • stdlib.math scalar helpers now use a shared signed-integer template bound for i8, i16, i32, and i64, preserving the selected result type.
  • stdlib.math.abs on the selected type's minimum now fails checked arithmetic; clamp with reversed bounds raises AssertionError; abs overflow raises OverflowError. These failures can be handled by exception statements.

Migration notes

  • Math helpers no longer convert every call to i32. Inferred arguments must have the same concrete signed type; use casts or explicit specialization, such as math.min<i64>(small, wide), when mixing widths. Floating-point, unsigned, Boolean, and nullable specializations remain unsupported.
  • CSV and Parquet operations live in stdlib.csv and stdlib.parquet; stdlib.arrow retains shared schemas, batches, and IPC. Use CSVStream and ParquetStream for explicit sessions instead of the removed CSV and Parquet class names. No compatibility aliases are provided. Module-level read_csv/write_csv and read_parquet/write_parquet remain the eager path.
