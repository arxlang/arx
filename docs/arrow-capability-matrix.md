### Foundation completion contracts

- **FND-001 — Scalar numerics and Boolean**
  - Baseline: Core signed and unsigned integers, floats, casts, and Boolean rules exist.
  - Required: Define exact Arrow cast, overflow, comparison, NaN, and non-finite behavior.
- **FND-002 — Null values**
  - Baseline: The language has none and finite unions, and Arrow arrays expose validity metadata.
  - Required: Define nullable scalar semantics, validity propagation, equality, ordering, casts, and branch behavior.
- **FND-003 — Strings and bytes**
  - Baseline: UTF-8 strings exist, and Arrow RecordBatch supports UTF-8 internally.
  - Required: Add owned and borrowed binary values, large offsets, Unicode conversion, view lifetimes, and zero-copy rules.
- **FND-004 — Decimal values**
  - Baseline: ASTx reserves decimal data-type kinds but has no usable decimal value model.
  - Required: Add types and literals, precision and scale checks, 32/64/128/256-bit representation, arithmetic, casts, and ABI rules.
- **FND-005 — Temporal values**
  - Baseline: Date, time, timestamp, and datetime types and literals exist.
  - Required: Add Arrow units, duration and interval types, timezone metadata, range checks, and conversion policy.
- **FND-006 — Parametric and structural types**
  - Baseline: Templates, tensors, DataFrames, structs, and unions provide partial foundations.
  - Required: Support recursive schema parameters, fixed sizes, dictionary types, union codes, field nullability, and canonical equality.
- **FND-007 — Compile-time values**
  - Baseline: Tensor dimensions and DataFrame fields carry selected static metadata.
  - Required: Provide checked type parameters for dimensions, decimal precision and scale, time units, fixed sizes, and schema fields.
- **FND-008 — Ownership and destruction**
  - Baseline: Strings and dynamic lists have semantic ownership. Native Arrow handles, including batches produced through irx_rb compatibility, now use checked shared or unique owner tokens, while IRx semantic ownership remains incomplete.
  - Required: Generalize ownership to handles, views, fields, calls, returns, temporaries, failures, classes, and generators.
- **FND-009 — Buffer and bitmap model**
  - Baseline: irx_buffer_view models data, owner, dtype, shape, strides, offset, and flags.
  - Required: Add checked bounds, validity bitmaps, variable-width offsets, alignment, endianness, and large-buffer overflow checks.
- **FND-010 — Collection sizes and indices**
  - Baseline: Existing APIs mix static metadata with several integer result widths.
  - Required: Standardize Arrow lengths, row counts, offsets, and indices on checked i64 semantics with explicit narrowing only.
- **FND-011 — Methods, overloads, and intrinsics**
  - Baseline: Typed calls and semantic sidecars exist without a canonical Arrow intrinsic registry.
  - Required: Add one typed builtin and intrinsic registry for containers and kernels that lowering consumes without re-resolution.
- **FND-012 — Error handling**
  - Baseline: The unified irx_arrow runtime uses fixed-width, Arx-owned status codes plus thread-local capture and immutable owned error snapshots. Deprecated irx_rb entry points preserve their integer results and translate failures from delegated unified operations.
  - Required: Implement recoverable/fatal propagation and failure cleanup across semantics, lowering, kernels, streams, and I/O.
- **FND-013 — Iteration and streaming**
  - Baseline: List iteration and initial generator support exist.
  - Required: Define Array and Series iteration, EOF, early close, cancellation, backpressure, and deterministic stream cleanup.
- **FND-014 — Classes and aggregate storage**
  - Baseline: Struct and class support exists, but general class destruction is incomplete.
  - Required: Add deterministic field destruction and move rules before aggregates may store owning Arrow handles.
- **FND-015 — FFI and opaque handles**
  - Baseline: C externs, version and feature queries, stable opaque handle kinds, checked owner-slot lifecycle operations, and cross-ABI RecordBatch C Data interchange exist.
  - Required: Add ownership and nullability annotations, complete C Data and C Stream contracts, and ABI conformance checks.
- **FND-016 — Modules, builtins, and standard library**
  - Baseline: Ambient builtins, bundled builtin modules, and a small standard library exist.
  - Required: Define stable intrinsic registration and public stdlib.compute, stdlib.io, and stdlib.dataset facades without an Arrow namespace.
- **FND-017 — Execution context**
  - Baseline: Runtime features can add native artifacts and linker flags, but there is no Arrow execution-context value.
  - Required: Add memory pool, allocator, thread count, cancellation, resource limits, and optional device selection.
- **FND-018 — Native packaging**
  - Baseline: Runtime sources build on demand from Arrow and PyArrow package metadata.
  - Required: Provide matched headers and libraries, platform discovery, clean-wheel execution, and cross-platform CI.

### Placement rationale

- **type-field-schema — Field and schema types:** Recursive fields, metadata, and nullability determine static validity and ABI representation.
- **type-nullable-scalar — Nullable scalar type:** Nullability participates in assignment, branching, kernel typing, scalar extraction, and schema compatibility.
- **type-array — Array type:** Array ownership, element nullability, calls, returns, indexing, and lowering require compiler knowledge.
- **type-series — Series and chunked-array type:** Series is Arx's public typed chunked-column value and must carry ownership and chunking semantics.
- **type-record-batch — RecordBatch type:** A batch schema and row count are part of its static and native value contract.
- **type-dataframe-table — DataFrame and table type:** DataFrame remains the Arx-native table surface; the Arrow Table handle is an implementation detail.
- **type-tensor — Dense tensor type:** Element type, rank, shape, strides, mutability, and device determine static safety and lowering.
- **type-stream — Batch stream type:** EOF, close, cancellation, iteration, and element ownership require compiler-visible resource semantics.
- **type-dataset-scanner — Dataset and scanner handle types:** Handle and expression types are builtin for schema safety; orchestration remains in stdlib.dataset.
- **type-execution-plan — Execution plan type:** Plan schemas, ownership, and execution state are compiler-visible while plan construction is library-oriented.
- **type-execution-context — Execution context type:** Memory pools, cancellation, limits, and thread policy need an opaque builtin value but not ambient syntax.
- **type-result-error — Recoverable result and data error types:** Fallible native operations need typed success and error control flow without Python exceptions or unchecked output slots.
- **construct-array — Array literals and builders:** Construction resolves element type, validity, allocation, partial failure cleanup, and result ownership.
- **construct-series — Series construction:** Chunk compatibility and result ownership must be checked before native construction.
- **construct-record-batch — RecordBatch construction:** Schema and equal-length validation are static when possible and use one native owning constructor.
- **construct-dataframe — DataFrame construction:** The existing native literal syntax remains builtin and gains the canonical schema and ownership model.
- **construct-tensor — Tensor literals and views:** Shape, strides, offset, owner lifetime, mutability, and overflow need semantic and lowering support.
- **core-length-shape — Length, row count, and shape queries:** These are universal safe collection queries with checked i64 results and natural language syntax.
- **core-index — Indexing and scalar extraction:** Bounds, scalar type, null validity, and view ownership must be proven or checked by the compiler.
- **core-slice — Zero-copy slicing:** Slicing creates borrowed or shared views whose bounds and owner lifetime need compiler support.
- **core-project-field — Field and column projection:** Static schemas resolve projections during analysis; dynamic schemas must return checked dynamic values.
- **core-null-inspection — Null inspection and validity:** Validity is part of core value semantics and must work without a library import.
- **core-cast — Checked casts:** The compiler resolves result type, overflow policy, nullability, and the exact native kernel.
- **core-iteration — Collection and stream iteration:** Iteration controls scalar validity, chunk traversal, early exit, stream close, and cleanup.
- **core-chunks — Chunk inspection and normalization:** Chunking changes representation, allocation, and ownership and must not be hidden in ordinary Arx code.
- **core-ownership — Retain, release, move, and borrow primitives:** Ordinary Arx values get safe deterministic semantics; users do not balance native reference counts.
- **compute-arithmetic — Elementwise arithmetic:** Natural operators use typed kernel resolution and preserve Arx overflow and null rules.
- **compute-comparison — Elementwise comparisons:** Comparisons are native operators whose nullable Boolean result type is decided during analysis.
- **compute-boolean — Elementwise Boolean and Kleene logic:** Boolean operators need language-defined three-valued behavior and typed kernel selection.
- **compute-selection — Selection and conditional kernels:** Typed intrinsics back a discoverable domain module without adding keywords or an Arrow namespace.
- **compute-aggregate — Aggregate kernels:** Aggregates need option types and typed scalar results but are better organized as domain functions.
- **compute-sort-rank — Sort, partition, and rank kernels:** Ordering policy and structured options belong in stdlib.compute over resolved intrinsic calls.
- **compute-set-lookup — Set and lookup kernels:** These are typed kernel families with nontrivial result schemas and options, not new syntax.
- **compute-string — String and binary kernels:** A typed registry can expose the long-tail kernel family without parser special cases.
- **compute-temporal — Temporal kernels:** Units, timezones, formats, and result types are resolved by builtins and organized in stdlib.compute.
- **compute-nested — Nested and encoding kernels:** Recursive result typing needs intrinsic metadata while the function families stay out of ambient syntax.
- **compute-cumulative — Cumulative, sliding, and vector kernels:** Long-tail analytics use the same typed registry and execution context without becoming compiler syntax.
- **compute-options — Compute option values:** Closed typed option records are compiler-known declarations exposed through the compute facade.
- **io-ipc — IPC stream and file I/O:** I/O needs policy and options, while native intrinsics retain ownership and status handling.
- **io-csv-json — CSV and JSON I/O:** Format options and streaming policy belong in stdlib.io over optional native runtime features.
- **io-parquet — Parquet I/O:** Projection, row groups, codecs, and pushdown are library policy backed by typed native primitives.
- **io-filesystem — Filesystem and URI operations:** Filesystem selection and credentials are policy-heavy and feature-gated rather than ambient language behavior.
- **dataset-open — Dataset discovery and opening:** Dataset orchestration is a domain API while schema and native handles remain compiler builtins.
- **dataset-scan — Scanner construction and execution:** Typed expressions and schemas are builtins; scan planning and execution form a composable library API.
- **dataset-fragments — Fragments and partitioning:** These domain operations expose typed handles and metadata without adding core syntax.
- **dataset-acero — Acero plan composition and execution:** A focused typed plan API composes runtime primitives without turning Arx into a separate query engine.
- **interop-c-data — Arrow C Data import and export:** The stable interchange ABI is available to bridges, but ordinary Arx code should use safe native values.
- **interop-c-stream — Arrow C Stream import and export:** The callback ABI stays behind safe Stream ownership, EOF, cancellation, and close semantics.
- **interop-pyarrow — PyArrow conversion:** Python conversion belongs to ArxPy and must not appear in native Arx execution or the language namespace.
- **optional-flight — Flight clients and servers:** RPC dependencies are optional and capability-named rather than nested below an Arrow namespace.
- **optional-substrait — Substrait import and export:** Plan interchange is optional and named for Substrait, with compiler checks around unsupported extensions.
- **optional-dlpack-device — DLPack and device adapters:** Device dependencies and synchronization stay optional while compiler-known ownership prevents unsafe transfer.

### Module rationale

- **core-data-model:** These types and containers define Arx's native data model and are compiler builtins rather than an imported library.
- **tensor:** CPU dense and sparse types are language containers; non-CPU device execution remains separately optional.
- **extension:** Arx preserves registered extension identity and metadata but executes only extensions with explicit typed registrations.
- **c-data-stream:** The C Data and C Stream layouts are stable bridge ABIs hidden behind safe Arx values.
- **compute:** Common operations are builtin operators while the typed long-tail registry is exposed through stdlib.compute.
- **acero:** Focused plan composition is a dataset library surface backed by compiler-known schemas and handles.
- **io-core:** Arrow stream and file primitives implement public stdlib.io operations but are not a separate Arx module.
- **ipc:** IPC stream and file APIs are required native I/O with typed options and Stream ownership.
- **csv:** CSV readers and writers are required stdlib.io capabilities activated only when used.
- **json:** JSON readers are required stdlib.io capabilities with explicit schema and resource policies.
- **parquet:** Parquet is a required columnar format but remains an independently linked runtime feature.
- **parquet-encryption:** Encryption adds crypto and credential policy and is excluded from the mandatory runtime payload.
- **parquet-geospatial:** Geospatial logical metadata is preserved by core Parquet and interpreted only by an optional typed feature.
- **filesystem-local:** Local files and URIs are required for I/O and datasets without adding cloud dependencies.
- **filesystem-cloud-hdfs:** Provider SDKs, credentials, and platform dependencies ship only in the cloud companion runtime.
- **dataset:** Dataset, fragment, and scanner orchestration is a required domain facade over builtin typed handles.
- **flight:** RPC, TLS, and authentication dependencies are optional and named directly for the capability.
- **flight-sql:** Flight SQL is an optional protocol API and does not make SQL a core Arx language feature.
- **substrait:** Plan interchange is optional and accepted only for operations mapped to typed Arx primitives.
- **device-gpu:** CPU remains mandatory; device memory, synchronization, and transfers require an optional runtime.
- **orc-adapter:** ORC is a useful optional format adapter but is not part of the required CSV, JSON, Parquet, and IPC baseline.
- **tensorflow-adapter:** Framework-specific TensorFlow integration belongs in an external ecosystem package, not the native language core.
- **gandiva:** Arx already lowers typed operations through IRx and Arrow Compute; a second LLVM expression compiler is not supported.
- **stl-adapters:** C++-specific adapters may be used inside native bridges but are not stable Arx or C ABI surfaces.
- **telemetry:** Telemetry may instrument execution contexts but does not define language-visible data semantics.
- **testing-integration:** Upstream test utilities and integration executables are development inputs, not shipped public APIs.
- **util-vendored-generated:** Implementation utilities and vendored dependencies inherit the feature that uses them and have no public Arx identity.
- **python-bridge:** Python conversion belongs to ArxPy tests and adapters and is never a dependency of native Arx execution.
- **benchmarks-examples:** Upstream developer programs inform Arx tests but are not distributable language or standard-library APIs.

### Baseline notes

- **Null and Boolean:** Boolean arrays and validity metadata exist, but Arx has no unified nullable scalar semantics or three-valued compute rules.
- **Signed and unsigned integers and floats:** Primitive array and scalar types exist, but Arrow-specific cast, overflow, and collection semantics are not complete end to end.
- **Binary, large binary, and binary view:** No general Arrow binary value, offsets, view lifetime, or Arx bytes surface is implemented.
- **UTF-8, large UTF-8, and string view:** RecordBatch UTF-8 and large UTF-8 interoperate with PyArrow; general arrays, string views, DataFrame columns, and LLVM lowering do not.
- **Fixed-size binary:** The fixed byte width is not represented in the type system or native ABI.
- **Decimal32, Decimal64, Decimal128, and Decimal256:** ASTx reserves decimal data-type kinds, but precision, scale, values, semantics, ABI representation, and Arrow interoperability are absent.
- **Date, time, timestamp, duration, and interval:** RecordBatch date, time, and timestamp values work in Python; duration, intervals, complete unit metadata, timezone policy, and Arx-native containers remain incomplete.
- **List, large list, fixed-size list, and list view:** Ordinary Arx lists and fixed-width RecordBatch list children exist; recursive Arrow list schemas, large offsets, list views, and container lowering are incomplete.
- **Struct and map:** Fixed-width RecordBatch struct fields exist; recursive Arrow structs, maps, child ownership, and Arx container semantics do not.
- **Sparse and dense union:** Arx type unions are not Arrow dense or sparse unions; type codes, offsets, storage, and interchange are not implemented.
- **Dictionary encoding:** Index and value typing, ordered metadata, encode/decode operations, and interchange are absent.
- **Run-end encoded:** Run-end and value child types, validation, decoding, and interchange are absent.
- **Extension types:** The target is lossless storage and metadata preservation; execution will require separately registered extensions.

### Baseline notes

- **Arrow C Data interface:** Primitive arrays support import, export, copy, and move; variable-width, nested, dictionary, and other required Arrow types remain unsupported.
- **Arrow C Stream interface:** A local C Stream struct declaration exists, but the ownership, EOF, cancellation, and general stream bridge are not implemented.
- **Compute kernels:** Arx has scalar operators, but no typed Arrow kernel registry, options, execution context, native dispatch, or stdlib.compute facade.
- **IPC streams and files:** The separate Python RecordBatch API reads and writes IPC streams and files; native Arx Stream and stdlib.io APIs do not exist.
- **CSV, JSON, and Parquet:** No stdlib.io readers, writers, option types, projection, pushdown, or native runtime features exist for these formats.
- **Filesystem, Dataset, and Scanner:** Dataset expressions, scan builders, path and URI types, partitioning, streaming output, and stdlib.dataset are absent.
- **Acero execution plans:** Typed plan nodes, schema propagation, execution ownership, cancellation, and bounded-memory behavior are absent.
